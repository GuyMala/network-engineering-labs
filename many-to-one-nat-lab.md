# Configure Many-to-One NAT (PAT / Overload)

**Date:** [fill in]
**Certification Track:** CCNP Enterprise
**Tools Used:** EVE-NG, Cisco IOS (IOSv, version 15.9)

---

## 1. Objective
Configure NAT overload (PAT) so that all hosts on an inside subnet share a single outside IP address for outbound traffic, distinguished by port number rather than by unique outside addresses — and route between routers using RIPv2.

## 2. Topology

- **Devices:** Router1 (NAT + RIP), Router2 (RIP only, no NAT), PC1, PC2
- **Role of each device:**
  - Router1 sits between PC1's subnet and the transit link — performs NAT overload on outbound traffic.
  - Router2 is a plain router with no NAT — it only needs a route back to the transit network to return traffic correctly.

## 3. IP Addressing Table

| Device | Interface | IP Address | Role | Notes |
|---|---|---|---|---|
| Router1 | Gi0/0 | 192.168.1.1/30 | NAT outside, transit link | `ip nat outside` |
| Router1 | Gi0/1 | 192.168.101.1/24 | NAT inside, PC1 gateway | `ip nat inside` |
| Router2 | Gi0/0 | 192.168.1.2/30 | Transit link | No NAT |
| Router2 | Gi0/1 | 192.168.100.1/24 | PC2 gateway | No NAT |
| PC1 | eth0 | 192.168.101.2/24 | Inside host | GW: 192.168.101.1 |
| PC2 | eth0 | 192.168.100.2/24 | Remote host | GW: 192.168.100.1 |

## 4. Configuration Steps

**Interface roles (Router1):**
- *What I configured:* Gi0/0 (facing Router2) as NAT outside, Gi0/1 (facing PC1) as NAT inside.
- *Why:* Defines the translation boundary — traffic from the inside network gets translated as it exits toward the outside interface.
- *Key commands:*
```
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.252
 ip nat outside

interface GigabitEthernet0/1
 ip address 192.168.101.1 255.255.255.0
 ip nat inside
```

**NAT overload configuration:**
- *What I configured:* An ACL matching PC1's subnet, then bound it to the outside interface with the `overload` keyword.
- *Why:* `overload` is what makes this PAT — all matching inside hosts share Router1's single outside interface address (192.168.1.1), differentiated by source port.
- *Key commands:*
```
access-list 12 permit 192.168.101.0 0.0.0.255
ip nat inside source list 12 interface GigabitEthernet0/0 overload
```

**RIPv2 routing:**
- *What I configured:* RIPv2 on both routers, but Router1 only advertises the transit network (192.168.1.0), not PC1's real subnet (192.168.101.0).
- *Why:* Since NAT hides 192.168.101.0/24 behind 192.168.1.1, Router2 never needs a route to the real inside subnet — it only needs reachability to 192.168.1.0/30 to send return traffic to the translated address. Advertising the inside subnet would be unnecessary and would leak topology that NAT is meant to hide.
- *Key commands:*
```
! Router1
router rip
 version 2
 network 192.168.1.0

! Router2
router rip
 version 2
 network 192.168.1.0
 network 192.168.100.0
```

## 5. Verification
```
Router1#show ip nat translations
Pro Inside global      Inside local       Outside local      Outside global
icmp 192.168.1.1:53791 192.168.101.2:53791 192.168.100.1:53791 192.168.100.1:53791
icmp 192.168.1.1:54303 192.168.101.2:54303 192.168.100.1:54303 192.168.100.1:54303
icmp 192.168.1.1:54559 192.168.101.2:54559 192.168.100.1:54559 192.168.100.1:54559
```
This confirms PAT/overload behavior: every translation uses the *same* inside global address (192.168.1.1) but a *different* port number per session — the signature of many-to-one NAT, versus the distinct addresses seen in the many-to-many NAT lab. Traffic here was generated by pinging 192.168.100.1 (Router2's interface) from PC1.

## 7. Lessons Learned
- The `overload` keyword is the entire difference between many-to-many NAT and PAT — same basic `ip nat inside source` structure, one keyword changes the behavior completely.
- Deliberately not advertising the inside subnet via RIP is a realistic design choice: NAT already hides those addresses, so advertising them would be redundant and would undercut the point of NAT.
- Port numbers in `show ip nat translations` are the fastest way to visually distinguish PAT from dynamic NAT without reading any config.
